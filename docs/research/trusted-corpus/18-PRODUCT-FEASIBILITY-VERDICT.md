# 18 — Product Feasibility Verdict: the 25 questions, answered directly

**FINAL VERDICT: GO WITH SOURCE ARCHITECTURE CHANGE.**
Literal answer to the Founder's question ("can the WHOLE SGK/SGV K-12 corpus be turned into a trusted learning corpus with a pipeline that scales, automatically?"): **NO — not the whole corpus, not automatically, not at < 0.1 % false trust with the stacks that exist today.** What the evidence supports: a **block-level, fail-closed, structured source** built on a layout-model parser + independent verifier + deterministic guards + a role layer can make **≈ 68 % of pages / ≈ 84 % of blocks on the easy-to-medium part of the corpus** trustworthy enough to teach from, with false trust measured at 0 % on plain prose pages and 6–12 % on hard pages (to be driven down by guards and bounded human review), while **math notation, diagrams/timelines/maps and elementary picture pages stay withheld** (image-first or human). That is a product, but it is not the product thesis as written ("3,679 lessons from the books"); the thesis must change to "a growing trusted subset, never a silently corrupted whole".

| # | question | answer (MEASURED unless marked) |
|---|---|---|
| 1 | Is the current extraction safe enough? | **No.** WAL-204 order: 1 trusted block in 3 is wrong (FTR 0.32), 103 critical-error events on 30/38 hard pages. WAL-206 XY-cut: safer (FTR 0.12) only because it withholds 76 % of blocks; 12 % of what it trusts is still wrong; its question labeller has 0.69 precision. |
| 2 | Is the failure mainly OCR or layout/reading order? | **Layout + roles**, not OCR. Same OCR under three layout analyses gives text accuracy 0.902 / 0.907 / 0.954 and splices 24 / 17 / 6. OCR's own ceiling (~4–5 % CER on hard pages, ~1 % on prose) comes from ~100-ppi scans, decorative fonts and notation — shared by every stack. |
| 3 | % of the corpus affected? | Pages with ≥ 1 hard layout feature: **64.5 %** (side-by-side regions 29.5 %, sidebars 26 %, coloured boxes 23 %, diagrams 19 %, formulas 9 %, tables 7 %). Lessons with no hard feature on any page: **3 %**. Lessons free of the *unhandled* features (formula/diagram/colour-heavy/table/3-col): **555 / 3,381 (16 %)**. |
| 4 | How many real layout families? | **241 feature combinations; 20 cover 80 % of pages, 39 cover 90 %, 62 cover 95 %.** Families are combinations of ~10 features, not types — handle features, gate on features. |
| 5 | Do a few parser/layout strategies cover most of the corpus? | **Yes for prose/questions/sidebars/boxes (~68 % of non-sparse pages), no for the rest.** One layout-model parser (Docling) + one independent geometry (XY-cut) + guards covers the former; math, diagrams, elementary pictures need different paths (image-first or formula-capable). |
| 6 | Best candidate? | **Docling 2.126 + Apple Vision (ocrmac)** on this hardware: text 0.954, order 0.987, fidelity 0.975, 3.3 s/page, MIT, offline, deterministic. **Marker/Surya 2** is more faithful (order 0.991, tables/formulas as objects, FTR 0.093) but 129 s/page here (GPU needed) and GPL. MinerU: great layout, no Vietnamese OCR. PyMuPDF4LLM: not applicable (no text layer, no Vietnamese OCR). |
| 7 | Ensemble/cascade needed? | **Yes.** Best single stack FTR 0.09–0.14; agreement cascades: marker ▸ docling 0.065, docling ▸ xycut + math guard 0.121 — and only deterministic guards removed the shared-mode errors. |
| 8 | Where does vision/VLM help? | As **text verifier** (marker ▸ vlm FTR 0.071 ≈ marker ▸ docling 0.065) and for reading gold; **not** as a parser (no bboxes/roles on 20/22 pages), **not** for math (flattened the same way). Its real value is the human-like annotator role, which this study used to write gold. |
| 9 | Is a VLM reliable as verifier? | **Partly.** 3B model: text 0.944, no fabricated sentences seen on 31 pages, but ignores structure and costs 81 s/page; 3-way voting with it *lowered* TLSR (0.61). Use text-only agreement, never as truth, and measure hallucination before scaling. |
| 10 | Re-OCR / re-parse the whole corpus needed? | **Re-parse yes eventually; re-OCR no** (Apple Vision text is the stable part). **Not now** — the gate is not passed (12). Slice reprocess (Science, 2,680 pages) once the role layer exists. |
| 11 | Cost/time/storage? | Docling: **≈ 58 h** single-Mac (≈ 30–35 h with 2 processes), ≈ 1.1 GB JSON; SDM ≈ 2–2.5 GB. Marker: 94 days on this Mac / 1–3 days on a GPU (ESTIMATED). Study itself: ≈ 6 h Mac time, no cloud spend. |
| 12 | Expected / measured TLSR after reprocessing? | Measured on hard gold: docling alone 0.814, cascade 0.67–0.76; pilot gate coverage 0.85 (true TLSR on pilot pages ESTIMATED 0.75–0.80, unannotated). Corpus-wide ESTIMATE: ≈ 0.75 of learning blocks on handled pages, ≈ 0.55–0.60 of all learning blocks after feature gating. |
| 13 | False trust? | Measured best: **6.5 %** (marker ▸ docling, 32 pages), **12 %** (docling ▸ xycut + math guard, 38 pages) on hard pages; **0 %** on the plain-prose page; ESTIMATED 5–10 % corpus-wide before guards, target < 1 % after guards + review — **< 0.1 % is not demonstrated by anything in this study.** |
| 14 | Remaining critical-teaching-error classes? | Shared-mode: flattened math; merged adjacent boxes; dropped headers/enumerators. Semantic order: timelines, 2-D schemes, bubbles. Roles: non-question-as-question (no role layer). Source: wrong lesson (10/38 pages), SGV teacher text/answers. |
| 15 | Which layouts stay untrusted? | Formula pages (TLSR 0.55, FTR 0.17), speech-bubble pages (0.48 / 0.25), colour-heavy elementary pages (0.36 / 0.30), tables (FTR 0.19), diagram/map/timeline pages (semantic order), two-lesson pages. |
| 16 | Can they be failed closed? | **Yes, by feature detection** — the census flags every one of them per page (formula/table/diagram/colour-heavy) and the math guard flags blocks; a page-feature guard withholds prose extraction on diagram/map pages. Cost: the 16 % of lessons that are fully clean become the *fully* trusted set; the rest are partially trusted. |
| 17 | How many / 3,679 lessons have a Trusted Source? | **Today: 0 at the Founder's bar.** With the measured cascade + feature gates: **≈ 555–603 lessons (15–16 %) fully sourceable** (no unhandled feature on any page), **≈ 2,800 partially** (prose/questions trusted, math/diagram/visual blocks withheld); Toán 4 / 554, KHTN 4 / 145, Vật lí 1 / 82 fully — the math/science lessons the product cares most about are the least sourceable as text. |
| 18 | How does SGV pairing change? | From page ranges to `answer_of` relations keyed by printed enumerators + table cells; needs enumerator-preserving blocks, table objects (Marker-class), SGV lexicon (GV…/ĐÁP ÁN/M:) and an answer-leak guard. Today's SGV structure is absent for many books (`07-sgv-toan-7` → no range). |
| 19 | How does the pattern census change? | Directive units on identical pilot pages: **49 → 199 (4×)**. The registry counts are extractor artefacts; recompute only on a role-labelled SDM. SELECT_MCQ becomes detectable but stays ungradable without keys; formula patterns cannot be sourced as text. |
| 20 | Evidence for "one capability → many lessons"? | **Yes, for layout**: one layout model lifted Toán 5 from 3/50 trusted pages to 77 % trusted blocks and removed the interleave class across all subjects. **No, for roles/math**: no capability tested lifts questions or formulas — those are new capabilities, not tuning. |
| 21 | Large-scale manual review needed? | **Not for the corpus; yes for shipped lessons.** Human review of the WITHHELD/CONFLICT queue on the lessons that reach a Surface, plus a periodic false-trust audit on trusted blocks (statistical sample). |
| 22 | If so, what ratio? | ESTIMATED 15–20 % of blocks withheld on handled pages (pilot: 15–17 %) ≈ 1 min/block → for a 100-lesson release (~1,500 pages, ~20 k blocks) ≈ 3–4 k blocks ≈ 50–65 person-hours; plus a 2 % trusted-block audit. |
| 23 | Can the pipeline scale to all K-12? | **Compute: yes** (58 h Docling; census 3 min). **Trust: no, not uniformly** — it scales as "trusted where handled, withheld where not", and the withheld share is subject-dependent (Toán/Vật lí/KHTN highest). |
| 24 | Biggest residual risk? | **Silent agreement on a shared error** (two stacks flatten the same fraction or merge the same boxes) → TRUSTED wrong content. Bounded only by deterministic guards + structurally different verification for math/boxes + continuous audit. |
| 25 | Should Học cùng SAM keep investing? | **Yes — in the source architecture, not in the current extractor and not in pattern expansion.** Build the SDM + block trust + role layer + guards; ship from the trusted subset; keep math/visual lessons image-first until a formula path is measured. If the product cannot accept a trusted subset that starts at ~16 % of lessons fully and grows, then the thesis "SAM teaches every lesson from the books" is not feasible with automated ingestion and should be revised. |

## Why not the other verdicts

- **GO** (as is): rejected — the current pipeline fails on 1 in 3 blocks or withholds 3 in 4; no path to < 1 % false trust without changing the source layer.
- **UNCERTAIN — MORE EVIDENCE REQUIRED**: rejected for the architecture question — the evidence is sufficient to say the current source layer cannot be trusted and a block-level structured source with cascades can be, on the handled part. It *is* the honest label for two sub-questions: the corpus-wide false-trust rate (needs ≥ 3,000 validated blocks) and math/diagram sourcing (needs a formula-capable path measured on gold).
- **NO-GO FOR AUTOMATED K-12 INGESTION**: rejected as a whole, accepted for the literal reading — fully automated ingestion of *everything* at teaching-grade trust is not supported by any measurement here.
