## 4. Which abstraction is truly cross-domain — the answer

1. **The document layer is cross-domain.** Blocks with provenance and per-element trust, structural withholding, header boundaries, printed pages, reading order, verbatim-only text with rule ids — all carried History unchanged. Its failures are *OCR character classes and page-level guards*, not model failures.
2. **The semantic layer is per-shape, not per-subject, and the shapes are text-pattern rules.** `TimelineSemantic` needed nothing from Science; it needed one deterministic rule over prose («Name (year)») — the same kind of rule as `tsl-enumerated-steps-v1`, on a different pattern. The general abstraction is «a rule that projects trusted blocks into a typed shape and keeps the block id» — not Process or Timeline themselves.
3. **The validator abstraction generalises only as «a pure function over a typed shape stated by the book».** History got one because the book *states* the events; Bài 17 has none because the book states procedures, not answers. So «validator exists ⇔ SGK states the fact» is the cross-domain rule; the arithmetic in the fraction validator was incidental.
4. **The tutor layer does not generalise by copying scripts** — Science's three hand-written asks were lesson-specific. What generalised was the *typing* (`TutorScript`/`AskStep` with `keySource`, ≤ 2 hints, options, leak guard): History's steps are generated from the typed shape and still fit the same runtime. The History-specific behaviours (who/when, before/after, cause/effect, source awareness) are functions of the shape, and would work on any lesson whose prose enumerates dated events with a sourced story.
5. **What is not cross-domain and must stay per-family:** the role lexicon (attribution, sub-questions, story-box labels), the page-furniture strings (Chủ đề vs Chương, no «Em đã học»), and the guards' page-level heuristics (colour-heavy). These are pipeline vocabulary, not model shape.
